== Production considerations

This solution runs on a single broker with no authentication so that it starts in seconds. Before you reuse the design in production, work through this table.

[cols="1,2,2"]
|===
| Area | In this solution | In production

| Brokers and replication
| [One broker, replication factor 1]
| [Three or more brokers, replication factor 3, rack awareness. Link the deployment docs.]

| Security
| [Plaintext, no authentication]
| [TLS, SASL/SCRAM or mTLS, ACLs per service. Link the security docs.]

| Partitions
| [Fixed partition counts sized for the demo]
| [Size partitions for peak throughput and consumer parallelism. Link the partition guidance.]

| Schema validation
| [Schemas registered, no broker-side validation]
| [Enable schema ID validation on the topics. Link the schema registry docs.]

| Consumer scaling
| [One instance per consumer group]
| [Scale on consumer lag; keep instances at or below partition count.]

| Data retention
| [Local disk, default retention]
| [Tiered Storage for long retention and replay. Link the Tiered Storage docs.]

| Idempotency and delivery
| [At-least-once with idempotent producers]
| [Transactions or exactly-once where the sink needs it. Link the producer docs.]

| Dead-letter handling
| [DLQ topic, no alerting]
| [Alert on DLQ growth, replay tooling, retention policy for the DLQ.]

| Observability
| [Console only]
| [Prometheus metrics, dashboards, alerts on lag and under-replicated partitions. Link the monitoring docs.]

| Disaster recovery
| [None]
| [Shadowing to a second cluster. Link the Shadowing docs.]
