== Why

The properties a migration has to preserve are exactly the ones this step creates: more than one version under a subject, a compatibility level set on the subject rather than inherited from the global default, and schema IDs assigned in an order that the source chose. A registry copy that renumbers IDs or flattens versions breaks every consumer that reads old records. The next steps check each of these on the destination.

== Why Redpanda

Nothing about this step is specific to Redpanda, and that is the point: the source is untouched Confluent Platform, and the shadow link you create next reads it through the same REST endpoints you just used (`/subjects`, `/subjects/<name>/versions`, `/config/<name>`). See xref:streaming:manage:schema-reg/schema-reg-api.adoc[] for the same API on the Redpanda side.

== What happens inside

`POST /subjects/orders-value/versions` makes the Confluent Schema Registry parse the Avro schema, check it against the subject's compatibility level (the global default until the `PUT /config/orders-value` call sets `BACKWARD`), assign the next global ID, and write it to its `_schemas` topic on the Confluent broker. The second `POST` for `orders-value` is checked against version 1 under `BACKWARD` and becomes version 2 with ID `3`. Posting the same schema text again would return the existing ID, which is why `make register-schemas` is safe to repeat.

Two subjects, versions `[1,2]` for `orders-value`, and `BACKWARD` on it. If the second `POST` in the script failed with HTTP 409, the schema in `orders-v2.avsc` is not backward compatible with version 1 (the new field needs a default). If `curl` cannot connect, the registry port is not `38081` on your host; check `CONFLUENT_SR_PORT` in `.env`.

== In production

[.production-note]
Your source registry already has its history. Before you create the link, list the subjects and compatibility levels you expect to see on Redpanda; `make compare` in xref:verify-replication.adoc[] is that list, checked by machine. Schemas that use Confluent-only features (rule sets, metadata, compatibility groups) need a decision before the link is created; see the Dead-letter handling row in xref:index.adoc#_production_considerations[Production considerations].
