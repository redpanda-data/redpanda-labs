= Start the environment
:page-layout: solution-step
:description: Bring up the two source databases, Redpanda with Tiered Storage and Iceberg topics, MinIO, an Iceberg REST catalog, Spark, and Redpanda Console with one command.
:page-solution-step-duration: 12

You start every piece of the pipeline except the pipeline itself: Postgres and MySQL with their change logs turned on, Redpanda configured for Tiered Storage and Iceberg topics, MinIO as the object store, an Iceberg REST catalog, Spark, and Redpanda Console. Nothing is captured yet and no table exists.

== What you do

. Choose one of two paths. Both end with the same running stack.
+
*Download the complete example* (sign in required). Unzip it and change into `cdc-to-lakehouse/`.
+
*Or build along.* Create a directory `cdc-to-lakehouse/` and save the files listed under _Files for this step_ into it, keeping the paths shown. Save `env.example` as `.env.example`, `Makefile.mk` as `Makefile`, and `spark/Dockerfile.txt` as `spark/Dockerfile`, and `chmod +x` the files under `scripts/`.

. Put a Redpanda Connect license key in `.env`. Copy `.env.example` to `.env`, then set `REDPANDA_LICENSE` to a trial or Enterprise Edition key. == Why

The two databases are real Postgres and real MySQL, not a producer pretending to be a database, because the parts of change data capture that break in production are the parts that belong to the database: the write-ahead log setting, the replication slot, the binary log format, and what a delete actually records. A fake source would hide all four.

MinIO is here for one reason that is easy to miss: Iceberg topics write through the cluster's Tiered Storage configuration, so the object store is not an extra component bolted on for the lakehouse. It is the same bucket, the same credentials, and the same code path Redpanda already uses to offload topic segments.

== Why Redpanda

Three cluster properties are the whole lakehouse side of this solution: `cloud_storage_enabled` for the object store, `iceberg_enabled` for the table writes, and `iceberg_catalog_type` with `iceberg_rest_catalog_endpoint` for the catalog. There is no sink connector, no separate writer process, and no compaction job to schedule. See xref:streaming:manage:iceberg/about-iceberg-topics.adoc[].

== What happens inside

Compose starts the stack in dependency order, and every service has a healthcheck, so `make up` returns only when all nine are passing. MinIO comes up first, then a one-shot `mc` container creates the `redpanda` bucket and idles, so that the bucket's existence is itself a healthcheck the catalog and the broker can wait on. The catalog starts pointed at that bucket as its warehouse.

Redpanda then starts with `--memory 1G` and one core, advertising `redpanda:9092` inside the compose network and `localhost:64092` outside it, and reports `Healthy: true` once its single Raft group has a leader. Postgres starts with `wal_level=logical` and runs `postgres/init.sql`, which creates the table, sets its replica identity, and inserts the five rows. MySQL starts with row based binary logging and runs its own `init.sql`. Console connects to Redpanda's Kafka API, Schema Registry, and Admin API. Spark and the `rpk` helper idle, waiting to be given commands.

If `make up` stops with a container marked `unhealthy`, run `docker compose logs <service>`. The two usual causes are Docker having less than 8 GB of memory available, which shows up as Redpanda failing to allocate `--memory 1G` or MySQL being killed during its first start, and a host port already in use, which you move with the matching `*_PORT` variable in `.env`. If the `catalog` container is unhealthy, check that `mc` reported healthy first: the catalog fails to start when its warehouse bucket does not exist.

== In production

[.production-note]
One broker, one MinIO container, and plaintext everywhere is a laptop stack. See the Brokers and replication, Security, and Kubernetes rows in xref:index.adoc#_production_considerations[Production considerations], and note that on Kubernetes both MinIO and the REST catalog need more than a straight port forward.
